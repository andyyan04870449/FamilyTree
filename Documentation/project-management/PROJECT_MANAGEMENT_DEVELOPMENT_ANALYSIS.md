# 專案管理系統開發需求分析

## 📋 專案概述
將現有的單專案家族樹系統改造為多專案管理平台，支援用戶創建、管理多個獨立的家族樹專案。

## 🎯 核心功能分析

### 1. 專案管理 CRUD 功能

#### 1.1 專案列表 (已完成前端 UI)
- **功能描述**: 以卡片形式展示所有專案
- **當前狀態**: ✅ 前端 UI 完成，使用模擬資料
- **需要開發**: 
  - [ ] 後端 API: `GET /api/projects`
  - [ ] 前端服務整合
  - [ ] 專案卡片的真實資料綁定

#### 1.2 新增專案 (已完成前端 UI)
- **功能描述**: 創建新的家族樹專案
- **當前狀態**: ✅ 前端表單完成
- **需要開發**:
  - [ ] 後端 API: `POST /api/projects`
  - [ ] 專案 ID 生成邏輯 (userID-YYYYMMDDHHMMSS)
  - [ ] 專案初始化流程
  - [ ] 前端服務整合

#### 1.3 編輯專案 (已完成前端 UI)
- **功能描述**: 修改專案基本資訊
- **當前狀態**: ✅ 前端表單完成
- **需要開發**:
  - [ ] 後端 API: `PUT /api/projects/{id}`
  - [ ] 前端服務整合
  - [ ] 資料驗證與更新邏輯

#### 1.4 刪除專案 (已完成前端 UI)
- **功能描述**: 安全刪除專案及相關資料
- **當前狀態**: ✅ 前端確認對話框完成
- **需要開發**:
  - [ ] 後端 API: `DELETE /api/projects/{id}`
  - [ ] 前端服務整合
  - [ ] 刪除時進行軟刪除處理，只需將資料表的狀態標記刪除，不需要真的刪除相關資料。
### 2. 專案切換與狀態管理

#### 2.1 專案狀態管理
- **功能描述**: 全域專案狀態管理
- **需要開發**:
  - [ ] Angular Service: `ProjectStateService`
  - [ ] 當前專案的全域狀態
  - [ ] 專案切換事件通知
  - [ ] 專案狀態有：進行中、已封存、已刪除(軟刪除，不需讓我用查看)

#### 2.2 專案開啟功能
- **功能描述**: 點擊專案卡片進入專案詳細操作
- **需要開發**:
  - [ ] 專案詳細頁面路由設計
  - [ ] 專案內容展示頁面
  - [ ] 專案資料預載入機制

### 3. 搜尋與篩選功能

#### 3.1 專案搜尋 (已完成前端 UI)
- **功能描述**: 按名稱、描述、標籤搜尋專案
- **當前狀態**: ✅ 前端搜尋框完成，使用本地篩選
- **需要開發**:
  - [ ] 後端搜尋 API
  - [ ] 搜尋結果分頁機制
  - [ ] 搜尋歷史記錄

#### 3.2 狀態篩選 (已完成前端 UI)
- **功能描述**: 按專案狀態篩選 (全部/進行中/已封存/(不需要顯示已刪除))
- **當前狀態**: ✅ 前端下拉選單完成
- **需要開發**:
  - [ ] 後端篩選 API 參數支援
  - [ ] 複合篩選條件支援

### 4. 統計與分析功能

#### 4.1 專案統計 (已完成前端 UI)
- **功能描述**: 顯示專案總數、進行中數量、人員總數、關係總數
- **當前狀態**: ✅ 前端統計卡片完成，使用計算值
- **需要開發**:
  - [ ] 後端統計 API: `GET /api/projects/statistics`
  - [ ] 即時統計資料更新
  - [ ] 快取統計資料機制

#### 4.2 專案進度追蹤
- **功能描述**: 專案完成度計算與顯示
- **當前狀態**: ✅ 前端進度條完成，使用模擬資料
- **需要開發**:
  - [ ] 進度計算邏輯設計
  - [ ] 進度更新觸發機制
  - [ ] 進度歷史記錄

### 5. 多專案資料隔離

#### 5.1 API 層面改造
- **需要開發**:
  - [ ] 所有現有 API 增加專案 ID 參數
  - [ ] 中介軟體: 專案 ID 驗證
  - [ ] 跨專案資料訪問控制

#### 5.2 前端服務改造
- **需要開發**:
  - [ ] 所有資料服務增加專案上下文
  - [ ] HTTP 攔截器自動注入專案 ID
  - [ ] 快取機制按專案隔離
